# Development

## Prerequisites

- Python 3.13 (the repository pins `3.13.0`; package metadata allows 3.12+)
- `uv`
- Docker with Docker Compose
- a Telegram bot token
- reachable PostgreSQL and RabbitMQ instances

## Configuration

Settings are loaded by `app.config.settings` in this order:

1. `APP_VERSION` is read from the process environment, defaulting to `dev`.
2. `app/config/envs/<APP_VERSION>.env` is loaded.
3. individual settings are read from the resulting environment.

Create a development configuration:

```bash
cp .env.example app/config/envs/dev.env
```

Required variables:

```dotenv
APP_VERSION=dev
BOT_TOKEN=...

DB_NAME=...
DB_USER=...
DB_PASSWORD=...
DB_HOST=...
DB_PORT=5432

AMQP_USER=...
AMQP_PASSWORD=...
AMQP_HOST=...
AMQP_PORT=5672
AMQP_VHOST=...
```

`AMQP_PORT` is part of the configuration contract but the current `AMQP_URL`
construction does not include it. Use a broker endpoint reachable through the
default AMQP port unless that code is changed.

Do not commit populated environment files. The `.gitignore` excludes `*.env`.

## Install and run

```bash
make install
make migrate
make app
```

`make app` runs the scheduler process with `APP_VERSION=dev` unless overridden:

```bash
make app APP_VERSION=qa
```

The scheduler requires PostgreSQL and RabbitMQ to be available before startup.
It opens debugpy on `0.0.0.0:5678` in `dev` and `qa`.

To run the RabbitMQ consumer separately:

```bash
SERVICE_TYPE=consumer APP_VERSION=dev uv run python -m app.main
```

## Make targets

| Command | Effect |
| --- | --- |
| `make install` | Sync locked dependencies |
| `make app` | Run the bot locally |
| `make app-up` | Build and start scheduler/notifier containers |
| `make app-down` | Stop application containers |
| `make app-logs` | Follow scheduler and notifier logs |
| `make app-config` | Render the Compose configuration |
| `make migrate` | Upgrade the configured database to Alembic head |
| `make migration MESSAGE=name` | Autogenerate a migration |
| `make format` | Format `app` and `tests` |
| `make lint` | Run Ruff checks |
| `make fix` | Format and apply safe Ruff fixes |
| `make typecheck` | Run mypy |
| `make check` | Format check, lint, unit tests, and compile check |
| `make test-unit` | Run tests without PostgreSQL |
| `make test-integration` | Start test PostgreSQL and run integration tests |
| `make test` | Run the complete suite |
| `make test-coverage` | Run the complete suite with coverage |

## Database migrations

ORM models live in `app/database/orm`; Alembic scripts live in
`app/database/alembic`.

```bash
make migration MESSAGE=add_booking_status
make migrate
```

Review autogenerated migrations before applying them. The Alembic environment
rebuilds the configured database URL with `host=localhost`, so migrations are
designed to run from the host against a published PostgreSQL port. This differs
from normal application configuration and matters when PostgreSQL is only
addressable by a Compose service name.

## Adding application behavior

A typical feature change follows this path:

1. Update or add Pydantic DTOs and ORM models.
2. Add repository queries and persistence operations.
3. Add service rules and domain exceptions.
4. Add typed callback data and keyboard builders if needed.
5. Add command, callback, or FSM handlers.
6. Register new routers in the package `__init__.py`.
7. Add unit tests; add integration tests for meaningful SQL behavior.
8. Generate and review a migration when the schema changes.

Keep transaction decisions out of handlers and repository methods used by the
unit of work. Let `DBSessionMiddleware` commit or roll back the update.

## Code quality

Ruff targets Python 3.12 syntax with an 88-character line length and checks
pycodestyle errors, Pyflakes, import ordering, and pyupgrade rules. Migration
versions are excluded.

Run before submitting changes:

```bash
make check
make typecheck
```
